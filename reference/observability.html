Metrics, logs, tracing and health checks

Logs say what happened. Metrics say how many. Traces join one request. HEALTHCHECK asks yes or no now.

Lesson: Metrics, logs, tracing and health checks. Docs: What is observability, signals, counter, exposition, naming, HEALTHCHECK, W3C trace-id.

Signals

  • Log — Day 19 StructuredLogger ctx plus trace_id.
  • Metric — Prometheus counter, scraped as text. Suffix _total.
  • Trace — 32 lowercase hex; all zeroes invalid; carried on traceparent.
  • Health — GET /health (Day 19) probed by Docker HEALTHCHECK.

# HELP quotes_http_requests_total HTTP requests
# TYPE quotes_http_requests_total counter

Probe

USER 1000
HEALTHCHECK --interval=30s --timeout=3s --retries=3 CMD ["wget", "-qO-", "http://127.0.0.1:8080/health"]
CMD ["java", "-jar", "quotes.jar"]
  • The command runs inside the container. Exit 0 healthy, 1 unhealthy, 2 reserved.
  • BusyBox wget on this Alpine pin. Loopback, not localhost. Not /metrics.
  • observedDockerfileOf renders the twin. Day 27 hardened.Dockerfile stays the contract.

Do

  • Prefix the counter with the app name. Put trace_id in the log map.

Do not

  • Increment or log inside rateOf / convertAmount.
  • HEALTHCHECK /metrics, curl, or localhost as the host.
  • Introduce otel4s, a Prometheus server, Grafana, Jaeger, slf4j/logback, Kubernetes probes, histograms, or Compose healthcheck:.
