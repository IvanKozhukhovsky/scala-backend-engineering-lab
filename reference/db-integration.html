Database integration tests

Start Postgres. Read host and mapped port. Migrate. Transact. Stop even on failure.

Lesson: Database integration tests. Docs: Postgres module, JDBC support, JUnit 4 Quickstart. This repo pins org.testcontainers:testcontainers-postgresql:2.0.5. Package: org.testcontainers.postgresql.PostgreSQLContainer. Image: postgres:16-alpine. Docker-API runtime required.

Layers

  • H2 mem — fast program check. Wrong engine.
  • postgresFlyway(...).load() — shape only; does not open Postgres.
  • PostgreSQLContainer.start() — live catalog, mapped port, real driver.

Harness

Resource.make(IO {
  val pg = new PostgreSQLContainer("postgres:16-alpine")
  pg.start()
  pg
})(pg => IO { pg.stop() })
  .use { pg =>
    run(pg.getJdbcUrl, pg.getUsername, pg.getPassword)
  }
  • Construction does not pull or listen. start waits (module log strategy, 60s).
  • Ask getHost() / mapped port. Do not hard-code localhost:5432.
  • getJdbcUrl is jdbc:postgresql://…, not jdbc:h2 or jdbc:tc:.

Migrate then transact

Flyway.configure()
  .dataSource(url, user, password)   // container credentials, not sa
  .locations("classpath:db/migration")
  .load()
  .migrate()

Transactor.fromDriverManager[IO](
  driver = "org.postgresql.Driver",
  url = url, user = user, password = password,
  logHandler = None
)
  • Same V1__ / V2__ as H2. select version() contains PostgreSQL.
  • Two transact calls are still two commits.

Do

  • Keep the H2 suites. This unit samples the engine.
  • Wrap start / stop in Resource.make (MUnit has no @Container).
  • Keep rateOf as the pure Map lookup this unit.

Do not

  • Treat jdbc:tc: as the integration test — it hides start/stop; default stop-on-last-close fights transact.
  • Point tests at a developer’s localhost:5432.
  • Put Docker or JDBC inside rateOf / convertAmount.
  • Introduce JUnit 5, testcontainers-scala, Flyway clean, or reusable containers. App Dockerfiles are a different image — see Docker packaging.
