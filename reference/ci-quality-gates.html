CI quality gates and dependency hygiene

Workflow is the recipe. A run is the process. Pin the runner, the action, and the CLI. Dependabot sees YAML; Scala CLI pins are reviewed by hand.

Lesson: CI quality gates and dependency hygiene. Docs: Actions, workflow syntax, runners, Dependabot, using directives. Pins: ubuntu-24.04, VirtusLab/scala-cli-setup@v1.16.0, scala-cli-version: "1.16.0".

Layers

  • Workflow — checked-in YAML. Not a running job.
  • Event — push to main, pull_request:, workflow_dispatch:.
  • Job — steps on one runner. Non-zero exit fails the step unless continue-on-error.
  • Local twin — python3 scripts/verify.py is the same three run: commands.

Recipe

name: CI
on:
  push:
    branches: [main]
  pull_request:
  workflow_dispatch:
permissions:
  contents: read
jobs:
  quality:
    runs-on: ubuntu-24.04
  • workflowOf(pipeline) renders the same text. Tests compare; they need not wait for GitHub.
  • contents: read is enough to check out and test. Not write-all.

Dependabot

version: 2
updates:
  - package-ecosystem: github-actions
    directory: /
    schedule:
      interval: weekly
  - package-ecosystem: docker
    directory: /packaging/quotes
    schedule:
      interval: weekly
  • github-actions at / watches .github/workflows.
  • docker directory is the folder that holds the Dockerfile.
  • Not sbt — this lab is Scala CLI. Pins in project.scala are reviewed by hand.

Do

  • Pin ubuntu-24.04, action tags, and scala-cli-version.
  • Keep MUnit on using test.dep.
  • Let a Dependabot PR go through the same fmt/test gate.

Do not

  • ubuntu-latest, uses: …@main, scala-cli-version: latest.
  • permissions: write-all. continue-on-error on fmt or tests.
  • package-ecosystem: sbt. using dep for MUnit.
  • Move Testcontainers to test.dep while Day 24’s main still starts a container.
  • Introduce action SHA pins, USER, image publishing, or required branch checks (later units).
