Relational SQL with doobie

Table is the catalog. sql interpolator binds. ConnectionIO does not connect yet.

Lesson: Relational modeling and SQL from Scala. Docs: Parameterized Queries, Selecting Data, Connecting. This repo pins org.typelevel doobie-core 1.0.0-RC13. Package: org.typelevel.doobie.

Row ↔ table

CREATE TABLE rate (
  code  VARCHAR NOT NULL PRIMARY KEY,
  cents INTEGER NOT NULL
)

final case class RateRow(code: String, cents: Int)
  • Map key → primary key. Field → column. NOT NULL → Int; nullable → Option.
  • query[RateRow] maps by SELECT-list position, not column names.

Statements as values

import org.typelevel.doobie.*
import org.typelevel.doobie.implicits.*

sql"select code, cents from rate where code = $code".query[RateRow]
sql"insert into rate (code, cents) values (${row.code}, ${row.cents})".update

findRate("EUR").sql   // … where code = ?
insertRate(row).sql   // … values (?, ?)
  • $code is a bind parameter. Do not write '$code' (that becomes '?').
  • s"…$code" concatenates and is how injection is written.
  • .option / .unique / .run yield ConnectionIO — still not a session. transact is the repository unit.

Do

  • Keep rateOf as the pure Map lookup this unit.
  • Assert on Query0.sql / Update0.sql without a database.
  • Name SELECT columns in case-class field order.

Do not (this unit)

  • Use Fragments.in, YOLO .check, generated keys, or batch Update.
  • Replace rateOf with SQL inside the HTTP routes.
