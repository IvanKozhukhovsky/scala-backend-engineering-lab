MUnit

A suite names behavior; assertEquals checks a public result against a spec literal.

Lesson: MUnit and behavior-oriented unit tests. Docs: Getting started, Assertions, Declaring tests, Scala CLI test.

Shape

class Day09Suite extends munit.FunSuite:
  test("ten percent off 1000 cents is 900"):
    assertEquals(discounted(1000, 10), 900)

assertEquals(obtained, expected). This repo pins MUnit 1.0.4 in project.scala.

Run

scala-cli test .
scala-cli test . --test-only 'day09.Day09Suite'

Test sources live under src/test/scala or end in .test.scala.

Do

  • Name the behavior a caller would care about.
  • Call the public function; compare to a literal from the spec.
  • Prefer assertEquals over assert(a == b) so failures show a diff.
  • Wrap Either results as Left(…) / Right(…) — a bare Int will not type-check against Either[…, Int].

Do not

  • Leave a test body empty — it still passes.
  • Recompute the implementation as the expected value.
  • Assert on private helpers, fields, or println output.
  • Use intercept for domain failure; this track uses Left.
