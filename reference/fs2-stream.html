FS2 streams

A Stream is a lazy pipeline of elements. compile runs it at the edge.

Lesson: Streaming fundamentals with FS2. Docs: FS2 Guide, Stream API. This repo pins fs2-core 3.12.2 and cats-effect 3.6.4.

Construct

import fs2.Stream

Stream.emit(1)
Stream(1, 2, 3)
Stream.emits(List("a", "b"))
Stream.empty
  • Stream[F, A] — effect F (often Pure or IO), element A.
  • Building a stream does not run effects or consume inputs.

Transform

s.map(_ + 1).filter(_ > 0).take(10)
s ++ Stream.emit(99)          // append
s.evalMap(a => IO(lookUp(a))) // effect per element
s.evalTap(a => IO.println(a)) // effect, keep element
  • map / filter / collect — pure steps on Stream[Pure, A] or inside a larger pipeline.
  • evalMap — suspend work in IO; do not call unsafeRunSync inside the callback.

Run (edge)

// F = IO:
import cats.effect.unsafe.implicits.global
s.compile.toList.unsafeRunSync()
s.compile.drain.unsafeRunSync()
s.compile.fold(0)(_ + _).unsafeRunSync()

// F = Pure:
s.compile.toList   // List[A], no IO
  • toList — collect all elements (tests, small data).
  • drain — run effects, discard output.
  • fold — aggregate without storing the whole stream.

Do

  • Keep domain logic pure; wrap lookups in IO(...) inside evalMap.
  • Run streams with compile.* only in IOApp or tests.

Do not

  • Call unsafeRunSync inside evalMap or library helpers.
  • Assume construction started I/O — same laziness as IO.
  • Introduce file/socket streams, through pipes, or parJoin before those units.

Prior effect units: IO, Resource and fibers.
