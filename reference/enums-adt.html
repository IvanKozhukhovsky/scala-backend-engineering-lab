Enums and ADTs

A closed set of alternatives. The compiler can see every case.

Lesson: Enums, ADTs and exhaustive matching. Related: Either / Try. Docs: Scala 3 Book — ADTs, E029.

Named values

enum Role:
  case Admin, Member, Guest

Role.Admin                         // a Role, not a String

Cases live on the companion. import Role.* lets you write Admin. An enum desugars to a sealed class — no new cases outside this file.

Cases that hold data

enum PortError:
  case NotAnInteger(raw: String)   // like a tiny case class
  case OutOfRange(port: Int)       // payload you can unwrap

Left(PortError.OutOfRange(0)): Either[PortError, Int]

Exhaustive match

error match
  case PortError.NotAnInteger(raw) => s"not an integer: $raw"
  case PortError.OutOfRange(port)  => s"out of range: $port"

Miss a case and the compiler emits E029, naming the gap. case _ silences that warning — use it for open types such as Int, not for a domain enum.

Do not

  • Encode alternatives as magic strings ("admin", "guest").
  • Put a free-form String on Left when the reasons form a closed set.
  • Use case _ on that closed set — a new case should break the build.

Backend uses

  • Roles, job states, HTTP methods: named-value enums.
  • Validation / domain errors on Either[E, A]: enums with payloads.
  • Compound records (user + email + age) stay case class.
