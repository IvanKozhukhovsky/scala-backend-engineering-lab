JSON codecs and API errors

Codecs at the rim. Either in the core. 400 vs 422 vs 404 vs 405.

Lesson: JSON codecs, validation and API errors. Docs: http4s JSON, Error Handling, RFC 9110 §15.5.1, §15.5.21. This repo pins http4s-circe 0.23.36.

Codecs

final case class RateOut(code: String, cents: Int)
  derives io.circe.Codec.AsObject

given EntityDecoder[IO, ConvertIn] = jsonOf[IO, ConvertIn]
given EntityEncoder[IO, ConvertOut] = jsonEncoderOf[IO, ConvertOut]
  • Encoder[A] writes JSON; Decoder[A] reads it.
  • jsonOf / jsonEncoderOf are the HTTP bridges.
  • Prefer attemptAs[A].value over as[A] without Ember.

Statuses

SituationStatusBody
Not JSON 400 malformed_json
JSON, wrong shape 422 invalid_json
JSON, domain rule 422 invalid_qty / unknown_code / …
Missing item URI 404 not_found
URI exists, wrong method 405 send Allow

http4s DSL: UnprocessableContent is 422 (RFC name; formerly Unprocessable Entity).

Do

  • Keep rateOf / convertAmount pure.
  • Give each failure a distinct {"error":…} string.

Do not

  • Map a missing body field and a missing URI to the same status or string.
  • Call req.as[A] and expect a 400 from HttpApp.run.
  • Introduce Ember, service-wide config loading, or logging middleware in this unit.
