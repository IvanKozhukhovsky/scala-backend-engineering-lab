HTTP and REST

URI names the resource. Method is the operation. Status is the outcome.

Lesson: HTTP and REST contracts. Docs: http4s DSL, RFC 9110 §9. This repo pins http4s-dsl 0.23.36.

Contract

  • GET — safe (read-only) and idempotent.
  • PUT / DELETE — not safe; idempotent.
  • POST — not safe; not idempotent.
  • 200 found · 204 success, no body · 404 no resource · 405 wrong method (send Allow).

Routes

import org.http4s.dsl.io.*
import org.http4s.headers.Allow
import org.http4s.implicits.*

HttpRoutes.of[IO] {
  case GET -> Root / "rates" / code =>
    rateOf(code) match
      case Some(n) => Ok(n.toString)
      case None    => NotFound()
  case _ -> Root / "rates" / _ =>
    MethodNotAllowed(Allow(GET))
}.orNotFound
  • First matching case wins.
  • Building routes does not bind a port or run Ok.
  • orNotFound turns no match into HTTP 404.

Run (edge)

val req = Request[IO](Method.GET, uri"/rates/EUR")
val res = rateApp.run(req).unsafeRunSync()
res.status
res.as[String].unsafeRunSync()
  • Tests and IOApp run the IO[Response[IO]].
  • Keep rateOf pure; HTTP only chooses the status.

Do

  • Return 405 (with Allow) when the URI exists but the method does not.
  • Return 404 when the item is missing or the path is unknown.

Do not

  • Treat every unmatched method as 404.
  • Put catalog rules only inside Ok { }.
  • Introduce Ember or integration-test servers in this unit. JSON codecs are scala-018.
