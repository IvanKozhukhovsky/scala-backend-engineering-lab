Resource, fibers, cancelation

Pair acquire with release. Cancel runs finalizers. Prefer background over bare start.

Lesson: Resources, fibers, cancellation and concurrency primitives. Docs: Concepts, Resource, Tutorial (resource + cancelation sections), GenSpawn. This repo pins cats-effect 3.6.4.

Fiber

for
  fiber <- work.start
  out   <- fiber.join   // Outcome: Succeeded | Errored | Canceled
yield out

fiber.cancel  // request stop; await finalizers
  • A fiber is a lightweight concurrent sequence of effects, not an OS thread.
  • start returns a handle; dropping it without cancel/join can leak work.
  • Cancelation is cooperative: request, then finalizers, then the canceler continues.

Resource

def conn(name: String): Resource[IO, Conn] =
  Resource.make(open(name))(c => close(c))

conn("orders").use(c => query(c))
  • make(acquire)(release); consume with use.
  • Release runs on success, error, and cancelation of the use body.
  • Nested resources release in reverse acquire order.
  • Do not use the handle after use returns — it is already released.

background

ticker.background.use { _ =>
  IO.sleep(2.seconds) *> work
}
  • background is a Resource around a started fiber.
  • Leaving the scope (or parent cancel) cancels the child.
  • Prefer this over bare start for “run while I do X.”
  • For “run these together,” prefer both / parMapN over manual join/cancel.

Do

  • Put every use of a scarce handle inside Resource.use.
  • Rely on cancelation + finalizers for timeouts and Ctrl-C via IOApp.
  • Keep domain rules as pure functions; wrap lifecycle in Resource / IO.

Do not

  • .start and forget the fiber handle.
  • Treat cancel like “thread is dead instantly with no cleanup.”
  • Reach for Ref / Deferred / FS2 before the next unit needs them.
  • Call unsafeRunSync inside acquire/release/use helpers in library code.
