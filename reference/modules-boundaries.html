Modules and dependency direction

A module is a package. The only import arrow is shell → core.

Lesson: Modules, boundaries and dependency direction. Docs: Scala 3 Book — Packaging and Imports, Tour — Packages and Imports.

Package

package day12.core

case class Item(sku: String, priceCents: Int)

def priceOf(items: List[Item], sku: String): Option[Int] =
  items.find(_.sku == sku).map(_.priceCents)
  • A package is a namespace. Same-package names need no import.
  • Convention: folder matches package. Scala does not require it; this repo does.
  • day12.core does not automatically see day12.shell.

Import

package day12.shell

import day12.core.{Item, priceOf}

def printPrice(items: List[Item], sku: String): Unit =
  priceOf(items, sku) match
    case Some(cents) => println(s"$cents")
    case None        => println("unknown")
  • import pkg.Name — one member. import pkg.{A, B} — a few. import pkg.* — the rest, not givens.
  • An import is a dependency arrow: this file depends on that package.

Direction

  • Shell imports core. Core does not import shell.
  • Tests of the decision import only the core (or live in that package).
  • Need the time? Pass now as data. A later trait is declared in the core package, implemented in the shell.

Do

  • Put Either / Option / copy decisions in *.core.
  • Keep println in *.shell.

Do not

  • Import the shell from the core — the compiler will allow it; review must not.
  • Treat this unit as an sbt/mill subproject split.
  • Introduce an IO type — that is a later curriculum phase.
  • Rename, hide, or import given here unless a later unit needs it.
