Traits and type classes

Shared behaviour: extend a trait, attach an extension, or supply a given.

Lesson: Traits, extension methods and type classes. Related: Enums and ADTs. Docs: Scala 3 Book — Type Classes, Extension Methods, Tour — Traits.

Classic trait

trait Show:
  def show: String                         // required
  def showHtml: String = s"<p>$show</p>"   // provided

case class Document(text: String) extends Show:
  def show: String = text                  // Document is a Show

Use when the types are yours and they truly share one hierarchy. You cannot new a trait.

Extension method

extension (c: Circle)
  def circumference: Double = c.radius * math.Pi * 2

Circle(0, 0, 5).circumference              // looks like a member

Adds a method after the type is closed. Import the extension if it lives elsewhere. Syntax only — it does not select an implementation per type by itself.

Type class

trait Showable[A]:
  extension (a: A) def show: String

given Showable[Person] with
  extension (p: Person) def show: String =
    s"${p.firstName} ${p.lastName}"

Person("John", "Doe").show

def showAll[A](as: List[A])(using Showable[A]): List[String] =
  as.map(_.show)

// compact form of the same using clause:
def showAll[A: Showable](as: List[A]): List[String] = as.map(_.show)

The type does not extends Showable. A given sits beside it — including for enums and for types you do not own.

Do not

  • Put log / JSON / email methods on the domain enum just because you can match there.
  • Write case _ inside a given that matches a closed enum.
  • Call .toString in a function that already has using Showable[A].
  • Force unrelated types into one extends Show hierarchy so they can be logged.

Backend uses

  • A service interface you implement: classic trait.
  • A helper on String or a library type: extension.
  • Show / JSON / equality for many unrelated types: type class (libraries later).
