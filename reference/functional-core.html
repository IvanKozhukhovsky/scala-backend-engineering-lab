Purity and functional core

Decisions return values. I/O stays in a thin shell around those values.

Lesson: Immutability, pure functions and functional core. Docs: Scala 3 Book — Immutable Values, Pure Functions.

Immutable update

val wallet = Wallet(1000)
val next = wallet.copy(balanceCents = 600)
// wallet is still Wallet(1000)
  • val cannot be reassigned. var can — avoid it in the core.
  • Collections: List / Vector / immutable Map. Transform; do not mutate.
  • Case classes: copy, not a var field.

Pure function

Same inputs → same output. Output depends only on the arguments and the implementation. No console, files, network, clock, hidden var, or mutated parameters. 

def debit(wallet: Wallet, amountCents: Int): Option[Wallet] =
  if amountCents <= 0 || amountCents > wallet.balanceCents then None
  else Some(wallet.copy(balanceCents = wallet.balanceCents - amountCents))

Unit is a warning: you probably called it for a side effect. println and System.currentTimeMillis are impure.

Functional core, imperative shell

def printDebit(wallet: Wallet, amountCents: Int): Unit =
  debit(wallet, amountCents) match
    case Some(next) => println(s"balance ${next.balanceCents}")
    case None       => println("refused")
  • Core: values in, values out. Tests call this.
  • Shell: read the world, call the core, write the world. Few conditionals.
  • The core does not call the shell. If you need the time, the shell reads it and passes it in.

Do

  • Keep domain rules in functions that return Option / Either / a new case class.
  • Assert against the core, not against captured stdout.

Do not

  • Mutate a var or a collection in place inside a decision.
  • Read the clock, a file, or the network from the core.
  • Introduce an IO type yet — that is a later curriculum phase.
  • Split packages and module boundaries here — that is scala-012.

Named pattern: Gary Bernhardt, Boundaries (the “functional core, imperative shell” split). The Scala 3 Book calls it a pure core with an impure wrapper.
