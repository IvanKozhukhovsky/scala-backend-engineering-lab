ScalaCheck

A property names an invariant; forAll checks it on generated inputs.

Lesson: Property-based testing and invariants. Docs: ScalaCheck User Guide, MUnit ScalaCheck.

Shape

import munit.ScalaCheckSuite
import org.scalacheck.Gen
import org.scalacheck.Prop.{forAll, propBoolean}

class Day10Suite extends ScalaCheckSuite:
  property("when lo <= hi, clamp stays in [lo, hi]"):
    forAll { (value: Int, lo: Int, hi: Int) =>
      (lo <= hi) ==> {
        val got = clamp(value, lo, hi)
        got >= lo && got <= hi
      }
    }

This repo pins MUnit 1.0.4 and munit-scalacheck 1.0.0 in project.scala (ScalaCheck 1.18.0 is transitive). property requires a Prop. test still works on the same suite.

Run

scala-cli test .
scala-cli test . --test-only 'day10.Day10Suite'

Generators

  • forAll { (n: Int) => … } uses the default Arbitrary[Int].
  • forAll(Gen.choose(1, 1000)) { n => … } uses inclusive bounds you name.
  • (premise) ==> result discards when the premise is false. Import propBoolean.

Do

  • Name the invariant a caller would care about.
  • Check a rule that can fail if the implementation is wrong (in range, identity, next page).
  • Prefer a tighter Gen when ==> would discard almost every case.
  • Prefer assertEquals inside forAll when both sides are values, not inequalities.

Do not

  • Restate the function body as the expected value.
  • Leave a property body empty — same green lie as an empty test.
  • Use full-range Int for products such as (page - 1) * pageSize in this unit.
  • Write a custom Arbitrary or Shrink yet.
