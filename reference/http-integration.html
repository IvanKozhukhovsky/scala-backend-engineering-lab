HTTP integration testing

Bind loopback. Talk HTTP. Release the socket. Keep in-process tests for the contract.

Lesson: HTTP integration testing. Docs: http4s Client, Service. This repo pins http4s-ember-server and http4s-ember-client 0.23.36.

Layers

  • HttpApp.run — function call. Relative uri"/health".
  • Client.fromHttpApp — same layer, client-shaped. No socket.
  • Ember server + Ember client — TCP, HTTP/1.1, absolute Server.baseUri.

Harness

EmberServerBuilder
  .default[IO]
  .withHost(ipv4"127.0.0.1")
  .withPort(port"0")
  .withHttpApp(app)
  .build

Resource
  .both(serve(app), EmberClientBuilder.default[IO].build)
  .use { case (server, client) =>
    run(server.baseUri, client)
  }
  • port"0" — OS picks a free port; read it from baseUri.
  • Bind loopback so baseUri is a destination, not 0.0.0.0.
  • Inject config values. Do not load env inside the test.

Client

client.expect[RateOut](base / "rates" / "EUR")     // 2xx or UnexpectedStatus
client.statusFromUri(base / "rates" / "JPY")       // just the code
client.run(req).use { res => res.as[ApiError] }    // 4xx body; finish inside use

Do

  • Keep a fast in-process suite for 400/422/404/405 mapping.
  • Sample the contract over the wire: 200, one 4xx, Date present.
  • Keep rateOf / convertAmount pure.

Do not

  • Treat Client.fromHttpApp as an integration test.
  • Call expect when you need a 404/422 body.
  • Hard-code 8080 in tests, or send the client to 0.0.0.0.
  • Introduce slf4j/logback, http4s Logger middleware, munit-cats-effect, or a database in this unit.
