Either and Try

Typed failure: a value, or a reason. Not a thrown crash to the caller.

Lesson: Either, Try and explicit failure. Related: Option, Enums and ADTs. API (Scala 3.3.8): Try, Either.

Which type

TypeFailure payloadUse when
Option[A] none (None) Absence, not a reason.
Try[A] Throwable Code that can throw.
Either[E, A] your type E A domain or validation reason.

Try

import scala.util.{Try, Success, Failure}

Try(raw.toInt)                 // Success(n) or Failure(ex)

t match
  case Success(n)  => n
  case Failure(ex) => fallback

t.map(_ + 1)                   // Failure stays Failure
t.toEither                     // Left(ex) or Right(n)

Either

Right(443): Either[String, Int]
Left("port too large")

e match
  case Right(port) => port
  case Left(reason) => fallback

e.map(_ + 1)                   // Left stays Left
e.getOrElse(80)                // unwrap Right, or default

Convention: Left is failure, Right is success. map / flatMap are right-biased.

Do not

  • Call .get on Try — it throws on Failure.
  • Use None when the caller needs to know why.
  • Throw to the caller of a function whose type is already Try or Either.

Backend uses

  • Parse a path or header that may throw: Try.
  • Validate a port, age, or amount: Either[String, A] (error types come later).
  • Lookup that may simply miss: still Option.
