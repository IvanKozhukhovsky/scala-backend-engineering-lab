Fibers are lightweight concurrent work

A fiber is a sequence of effects the runtime evaluates — a lightweight concurrent unit, not an OS thread.1 Your process has a main fiber (IOApp’s run). Other fibers are started from it. Creating millions is cheap; creating millions of JVM threads is not.

Cats Effect, Concepts · Fibers: fibers are “lightweight threads”; the IO runtime implements them in roughly 150 bytes each. 
for
  fiber <- IO.println("child").start
  _     <- fiber.join
yield ()

start returns a FiberIO handle. join waits for an Outcome: succeeded, errored, or canceled. Prefer higher-level helpers when you can; bare start is easy to leak. 2

Concepts · Concurrency: start / join are the primitives; prefer structured tools such as background so fibers are not abandoned.

Cancelation is a request, then finalizers

Cancelation is cooperative. Calling fiber.cancel asks the target to stop. The canceler waits until the target runs its finalizers and terminates. That is why cancelation can close files and sockets safely — if you registered finalizers.3

Concepts · Cancelation: cancel is a request; once cancelation starts, the fiber “will run all of its finalizers … before yielding control back to the canceler.”

Timeouts and racing work cancel the loser. Without finalizers, cancel still stops the fiber — and can leave a connection open. That is the leak cancelation is meant to prevent.

Resource pairs acquire with release

Resource[IO, A] packages “open A” with “always close A.” Build it with Resource.make, consume it with use.4

Cats Effect, Resource (std): make(acquire)(release) and use. Acquire and release are non-interruptible; release runs when use succeeds, fails, or is canceled. 
def connection(name: String): Resource[IO, Conn] =
  Resource.make(open(name))(c => close(c))

connection("orders").use { c =>
  query(c)
}

Nested resources in a for release in reverse acquire order. Outer release still runs if an inner step fails. Do not use and then keep using the handle outside the block — it is already closed.5

Resource: released in reverse order of acquire; “finalization happens as soon as the use block finishes.”

Prefer background over bare start

io.background is a Resource that starts a child fiber and cancels it when the resource scope ends (or when the parent is canceled). That is structured concurrency for background work.6

GenSpawn#background: “The child fiber is canceled in two cases: either the resource goes out of scope or the parent fiber is canceled.” Prefer this over cancelation-unsafe bare start. 
val ticker = IO.println("tick").foreverM
ticker.background.use { _ =>
  IO.sleep(2.seconds) *> IO.println("done")
}

When use exits, the ticker is canceled. You do not manually join / cancel unless you have a reason to manage the handle. Higher-level parMapN / both also start fibers for you and cancel siblings on failure — use those for “run these together,” use background for “keep this running while I do something else.”
