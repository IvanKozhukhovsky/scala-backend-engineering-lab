A tag moves; a SHA does not

GitHub’s security hardening wording: pinning an action to a full-length commit SHA is currently the only way to use it as an immutable release. A tag can be moved or deleted. A 40-character SHA names one git object. An abbreviated SHA is not enough.1

The Using SHAs page: verify the SHA is from the action’s repository, not a fork. Keep the human tag as a trailing comment so you can still read the version.

Day 26 already refused @main and latest. @v7 is better than that, and still a name the maintainer can retarget. The pin in this unit is the commit currently at that tag, plus # v7 so a human — and Dependabot — can see which release it is. Dependabot already watches github-actions at /; a SHA pin does not freeze you forever. It makes the bump a pull request.

Watch annotated tags. coursier/cache-action v8 is one: the git tag object has its own SHA (7e3b209d…). That is not the commit GitHub Actions runs. ActionPin.sha is the commit (95e5b102…). If a lookup returns "type": "tag", take one more hop to the commit.

USER is uid, default is root

Docker’s USER instruction sets the user (or UID) for later RUN and for runtime CMD / ENTRYPOINT. If you never set it, the default is root — uid 0. Docker’s own engine security note: containers are “especially” better if the process inside is a non-privileged user.2

Alpine’s BusyBox adduser is what this base image has — not Debian useradd. -D skips a password, -H skips a home directory, -u 1000 picks the uid. USER 1000 is the numeric form from the Dockerfile reference.

adduser needs root, so it runs before USER. CMD stays exec form after USER: PID 1 is still java; the uid is 1000. Day 25’s FROM, JAR, and ENV QUOTES_CODE do not change. rateOf is still Map.get. 

FROM eclipse-temurin:21-jre-alpine-3.24
WORKDIR /app
COPY quotes.jar quotes.jar
ENV QUOTES_CODE=EUR
RUN adduser -D -H -u 1000 app
USER 1000
CMD ["java", "-jar", "quotes.jar"]

packaging/quotes/Dockerfile stays the Day 25 contract. hardenedDockerfileOf writes the twin packaging/quotes/hardened.Dockerfile. Tests inspect the text; they do not docker build.

Layers remember what you COPY

Ciris already wraps tokens in Secret at the rim. That does not help if the Dockerfile ENV API_TOKEN=… or COPY .env. Those bytes are a layer. Day 25 already refused a token in ENV; this unit names the check secretInRecipe so a test can fail closed on token, password, secret, and .env. QUOTES_CODE=EUR is a currency code, not a Secret.
