transact is the session

Connecting: a Transactor knows how to get a java.sql.Connection, run the program, and clean up. program.transact(xa) is ConnectionIO ~> IO. The resulting IO “will connect to the database and execute single transaction.” Commit / rollback and closing the connection happen there — constructing ConnectionIO still does nothing.1

Connecting: DriverManager is “fine for development but inefficient for production.” Same chapter: transact adds commit/rollback and always closes the connection. Kleisli interpreters wait.

Compose with a for comprehension before transact if the statements should share one transaction — Connecting does this with two selects. Two separate transact calls are two sessions. Isolation and migrations wait until the next unit.

The repository holds the Transactor

Pass the Transactor in, the way Day 19 passed DeskConfig. The repository transacts Day 21’s Query0 / Update0. It does not become the catalog. rateOf stays Map.get. HTTP routes are not rewritten this unit.2

If convertAmount called transact, the unit test of qty < minQty would own a database. JDBC is the shell. The core still sees Option[Int]. 
final class RateRepository(xa: Transactor[IO]):
  def find(code: String): IO[Option[RateRow]] =
    findRate(code).option.transact(xa)

  def insert(row: RateRow): IO[Int] =
    insertRate(row).run.transact(xa)

Hikari for Postgres, DriverManager for tests

The homepage add-ons for this unit: doobie-postgres (driver 42.7.10 + type mappings), doobie-hikari (HikariCP transactor), doobie-h2 (H2 driver 2.4.240 for tests). Package stays org.typelevel.doobie. Postgres-specific types, LISTEN, and COPY wait.3

Extensions for PostgreSQL: the module “pulls in PostgreSQL JDBC Driver as a transitive dependency.” Driver class org.postgresql.Driver is what Connecting uses. Do not call postgresPool.use in this repo’s tests — there is no local world database yet.

Managing Connections: a pool is a lifetime-managed object, so HikariTransactor.fromHikariConfig is a Resource. Resource.use starts the pool (and typically opens a connection). Setting fields on HikariConfig does not. DriverManager has no pool to shut down — Connecting and the same chapter call it fine for tests. That is h2Xa.4

Hikari’s own example URL is jdbc:h2:mem:test;DB_CLOSE_DELAY=-1. Without the delay, H2 drops a mem database when the last connection closes — and transact always closes. Give each test a unique mem name so catalogs do not collide. H2Transactor.newH2Transactor waits; we do not need H2’s pool. 
def postgresHikariConfig(
  url: String, user: String, password: String
): HikariConfig =
  val config = new HikariConfig()
  config.setDriverClassName("org.postgresql.Driver")
  config.setJdbcUrl(url)
  config.setUsername(user)
  config.setPassword(password)
  config

def postgresPool(url: String, user: String, password: String) =
  HikariTransactor.fromHikariConfig[IO](
    postgresHikariConfig(url, user, password)
  )

def h2Xa(name: String): Transactor[IO] =
  Transactor.fromDriverManager[IO](
    driver = "org.h2.Driver",
    url = s"jdbc:h2:mem:$name;DB_CLOSE_DELAY=-1",
    user = "sa",
    password = "",
    logHandler = None
  )
