Config is a value

A running service still has a functional core. The new shell jobs are load settings and record what happened. Those are effects. Decode them once into ordinary Scala values, then pass the values in — the same move as passing time as data on Day 11.1

Scala 3 Book, Pure Functions: keep a pure core and an impure wrapper. Env and logs are the wrapper. Metrics, tracing, and health-check productization wait until a later unit.

QuoteConfig is a case class: service name, minimum qty, and a token. Routes take (config, logger). GET /health returns the name. The token never appears in a body. Ember still waits — you still run a constructed Request through HttpApp.

Ciris loads at the edge

Ciris’s ConfigValue is a description of how to read env, system properties, or files. It is not loaded until load[IO] — the same “description until the rim” idea as IO.2

Ciris Configurations: env, prop, or as fallback, as[Int] to decode, default when missing, parMapN to combine and accumulate errors, load to run in an effect. Stop before AWS, YAML modules, and refined/enumeratum from the quick example. 
import ciris.*

final case class QuoteConfig(
  serviceName: String,
  minQty: Int,
  apiToken: Secret[String]
)

val quoteConfig: ConfigValue[Effect, QuoteConfig] =
  (
    env("QUOTE_SERVICE_NAME")
      .or(prop("quote.serviceName"))
      .as[String]
      .default("quotes"),
    env("QUOTE_MIN_QTY")
      .or(prop("quote.minQty"))
      .as[Int]
      .default(1),
    env("QUOTE_API_TOKEN")
      .or(prop("quote.apiToken"))
      .secret
      .default(Secret("dev-token"))
  ).parMapN(QuoteConfig.apply)

quoteConfig.load[IO]  // IOApp / startup, not convertAmount

secret wraps the value in Secret. toString is the first seven characters of a SHA-1 hash, not the token. .value is the real string — use it only at a boundary that must send it, never in a log line or a JSON error.3

Ciris: Secret("…").toString is Secret(0a7425a)-style; value unwraps. Errors from .secret are redacted too. This repo pins ciris 3.15.0.

Prefer attempt[IO] in a test when you expect a missing key. load[IO] fails the task if required values are absent — that is the point of failing at startup instead of halfway through a request.

Keys beside the message

Logging is an effect. log4cats gives you StructuredLogger[F]: info(ctx)(msg) returns F[Unit], so it composes with IO instead of hiding a println inside a pure function.4

log4cats README: vanilla logger.info is a side effect; wrap it in an algebra so the program stays a value. Pass the logger in (this unit) rather than summoning F[_]: Sync everywhere. slf4j / logback and http4s Logger middleware wait — that middleware stringifies whole bodies. 
logger.info(Map("code" -> code, "op" -> "get_rate"))("ok") *>
  Ok(RateOut(code, cents))

The context map is the structure: code and op are fields, not fragments glued into one English sentence. Tests use StructuredTestingLogger and assert on ctx.get("code"). NoOpLogger is the silent stand-in when you only care about the HTTP status.

This repo pins log4cats-core 2.7.1 (Cats Effect 3.6 line). Do not put the token in ctx.
