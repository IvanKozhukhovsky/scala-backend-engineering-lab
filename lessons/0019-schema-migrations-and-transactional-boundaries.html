Flyway owns the schema

The Java API: integrate Flyway so “the application and its database will always be compatible.” It checks the schema version and applies pending migrations before the rest of the application starts. configure / dataSource / load build an immutable Flyway. migrate() is the work.1

Java API, 26 Aug 2026: OSS pin org.flywaydb:flyway-core:13.4.0 (Java 17+; this repo is JVM 21). migrate is idempotent — a second call on the same catalog applies nothing. Postgres support is the separate flyway-database-postgresql module; do not call migrate against a live Postgres in this unit.

Versioned SQL names are prefix VERSION separator DESCRIPTION suffix. Defaults make V1__Create_rate_table.sql. The API default location is classpath:db/migration. This repo puts those files under src/main/resources/db/migration and adds //> using resourceDir "./src/main/resources" so the classpath actually contains them.2

Quickstart-API: create src/main/resources/db/migration, then V1__Create_person_table.sql, then a second file V2__…. Re-running the program applies only what is still pending. Flyway also creates flyway_schema_history. Repeatable R__ scripts, undo, Java migrations, and clean wait. 
def migrateQuotes(url: String): IO[Int] =
  IO {
    Flyway.configure()
      .dataSource(url, "sa", "")
      .locations("classpath:db/migration")
      .load()
      .migrate()
      .migrationsExecuted
  }

One program is one transaction

Connecting: transact “will connect to the database and execute single transaction” and adds commit/rollback. A for comprehension before that call is one program — one transaction. The FAQ is blunt: compose ConnectionIO, then .transact(xa) once. “It’s useful for your APIs to expose values in ConnectionIO, so higher-level code can place transaction boundaries as needed.”3

Two separate transact calls already committed the first write. A failed second insert cannot un-commit it. Custom Strategy, withoutTransaction, and Testcontainers wait. rateOf stays Map.get. 
def bookRates(first: RateRow, second: RateRow): ConnectionIO[Unit] =
  for
    _ <- insertRate(first).run
    _ <- insertRate(second).run
  yield ()

bookRates(eur, gbp).transact(xa)           // both commit, or neither
insertRate(eur).run.transact(xa)          // session 1, committed
insertRate(eur).run.transact(xa)          // session 2 fails; EUR remains
