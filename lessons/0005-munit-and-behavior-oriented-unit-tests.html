FunSuite, test, assertEquals

This workspace already depends on MUnit 1.0.4 — the version the getting-started guide shows.1 A suite is a class that extends munit.FunSuite. Each test("…") is one case. Scala CLI treats files under src/test/scala (and names ending .test.scala) as test sources.2

MUnit, Getting started: assertEquals(obtained, expected). Docs use curly braces; this repo uses Scala 3’s colon syntax — same API.
Scala CLI: Test. Filter a suite with --test-only. 
package day09

def discounted(amountCents: Int, percent: Int): Int =
  amountCents * (100 - percent) / 100

class Day09Suite extends munit.FunSuite:
  test("ten percent off 1000 cents is 900"):
    assertEquals(discounted(1000, 10), 900)

First argument is the value you got; second is the value you meant. On failure MUnit prints a diff, not a bare “assertion failed” — that is the library’s stated goal.3 assert(discounted(1000, 10) == 900) can be true or false; assertEquals also shows 900 versus whatever you got.

MUnit, Writing assertions: assertEquals produces a diff. Comparing unrelated types (for example Right(42) and 42) is a compile error.

A backend test is the same shape as an HTTP contract later: call a public function, compare the result to a value the spec already named. Do not reach for fixtures, async tests, or exception interceptors in this unit. Failure in this codebase is Left, not a thrown exception.

A name is a specification

test("hello") tells a reader nothing. test("ten percent off 1000 cents is 900") is the requirement. Group several assertEquals under one name when they are the same behavior at different boundaries (Day 07 already did this for validPort).

The call must be the public function a caller would use — here discounted, later parseLimit. If a test would break after a rename of a local variable but the result for the caller is unchanged, the test was coupled to the implementation.

An empty test body still passes: MUnit only fails when the body throws.4 A suite with no assertions is a green lie.

MUnit, Declaring tests: a basic test “passes as long as the test body does not crash with an exception.”

Independent expected values

The expected argument must come from the spec, not from re-running the code: 

// independent — a person can check 900 without reading the function body
assertEquals(discounted(1000, 10), 900)

// tautology — this cannot disagree with the implementation
assertEquals(
  discounted(1000, 10),
  1000 * (100 - 10) / 100
)

Integer cents truncate toward zero: half of 5 cents is 2, not 2.5. That is observable behavior. Pin it with the literal 2, not by copying the / expression into the test.
