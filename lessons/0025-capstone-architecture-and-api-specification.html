The spec is the oracle

OpenAPI’s own wording: an OpenAPI Description is a language-agnostic interface so humans and computers can understand a service without access to source code, extra docs, or network traffic.1 learn.openapis.org calls that file a contract: the provider promises to honour it. Days 17–19 already had a contract — it lived as HttpRoutes. That is Scala. A reviewer who does not run the suite cannot see it. This unit moves the HTTP surface into a checked-in YAML document. Tests compare the file to openapiOf. Implementation is scala-030. Persistence wiring is scala-031.

OAS 3.1.2: the openapi field is the specification version. info.version is the document’s version. They are not the same string. This unit pins 3.1.2. OAS 3.2.0 exists; we do not need QUERY or $self.

OpenAPI lists allowed operations

Required fields: openapi, info (title + version), and at least one of paths, components, or webhooks.2 Paths start with /. A Path Item has get / post / … — the HTTP methods that exist on that path. Path templating /rates/{code} needs a parameter named code with in: path and required: true.

Structure: YAML or JSON. Field names are case-sensitive. Endpoints: response codes are quoted strings ('200').

OpenAPI lists operations you can do. It does not assert anything about operations that are absent from the document.3 POST is missing from /health in the quotes spec. That is not a documented 404. RFC 9110 still wants 405 + Allow: GET when the URI exists. scala-030 will implement that. This unit’s document simply does not list POST there.

Introduction: “OpenAPI lists operations that you can do, but it does not assert anything regarding operations not in the OAD.” 
openapi: 3.1.2
info:
  title: quotes
  version: 0.1.0
paths:
  /health:
    get:
      summary: Liveness
      responses:
        '200':
          description: Service is up

JSON bodies are Schema Objects under components.schemas, referenced with $ref: '#/components/schemas/RateOut'. Day 18’s 400 / 422 split stays: POST /convert lists both statuses on ApiError. GET miss stays 404. Do not put /metrics on this contract — a counter scrape is not a client resource.

One decision, one record

Nygard: keep a short record for an architecturally significant decision — structure, interfaces, construction technique — not every import. One decision per file. Title is a noun phrase. Context is value-neutral. Decision uses active voice: “We will …”. Status starts as accepted once you mean it. Consequences list the downsides too.4 His path was doc/arch/adr-NNN.md. This lab uses docs/adr/ next to the other public docs. Numbers are sequential and not reused. If you reverse a decision later, keep the old file and mark it superseded.

Documenting Architecture Decisions (Michael Nygard, 2011). One or two pages. Write it as a conversation with a future developer.

ADR 1 for quotes: the HTTP contract is the OpenAPI document, not HttpRoutes. The consequence you already know how to test: spec drift fails a file comparison. Generating server code from YAML waits; so does Swagger UI.

Primary source Read OAS 3.1.2 — What is the OpenAPI Specification? through the openapi vs info.version note. Read learn.openapis.org Introduction (contract; operations not in the OAD) and Structure (required fields; YAML). Skim API Endpoints for Path Item / quoted status codes. Read Nygard Documenting Architecture Decisions through the format (Context, Decision, Status, Consequences).
