Three signals, one question each

OpenTelemetry’s wording: observability is the ability to understand the internal state of a system by examining its outputs. In software those outputs are telemetry: traces, metrics, and logs. OpenTelemetry is a way to generate and export that data. It is not the dashboard. Jaeger and Prometheus are backends; this unit does not install them.1

Signals: a trace is the path of a request; a metric is a measurement captured at runtime; a log is a recording of an event. Profiles and baggage wait.

A health check answers a different question: can you serve right now? Day 19 already has GET /health. This unit adds the orchestrator’s recipe that calls it. rateOf still does not know about any of this.

A counter is a scrape, not a log

Prometheus counters only increase, or reset to zero on restart. Request counts and error counts are counters. Concurrent requests and memory are gauges — they go down. Do not use a counter for a value that can decrease. Histograms wait.2

Naming: an accumulating count SHOULD end with _total, with an application prefix: quotes_http_requests_total. Do not put user ids on labels — each combination is a new time series.

The wire contract is the text exposition: UTF-8 lines, # HELP / # TYPE before samples, a trailing newline. Prometheus scrapes that text (usually GET /metrics). Building scrapeOf does not talk to a Prometheus server. A client library can emit the same bytes later; you should be able to read them first.

The id in the header is the join key

OpenTelemetry traces are the path of a request: spans that share a trace_id, with parent ids for hierarchy. You do not need Jaeger to learn the join key. W3C Trace Context carries it on the traceparent header: 00-<trace-id>-<parent-id>-<flags>. The trace-id is 16 bytes, written as 32 lowercase hex characters. All zeroes is invalid.3

OpenTelemetry’s default propagator is this header. Day 19 already logs a Map. Put trace_id in that map so a log line can join the request. Do not unwrap a Ciris Secret into it.

traceIdFromParent reads the second field. isTraceId is the same shape of check as Day 27’s isFullSha — length and alphabet — with all zeroes forbidden. A Collector, an SDK, and span export wait.

HEALTHCHECK runs inside the container

Docker’s HEALTHCHECK instruction tells Docker how to test that a container is still working — including the case where the server process is alive but cannot handle new connections. The command runs inside the container. Exit 0 is healthy; 1 is unhealthy; 2 is reserved. Status starts as starting, then healthy / unhealthy after consecutive failures (--retries, default 3).4

Options you pin: --interval=30s (the default), --timeout=3s (the docs’ example timeout), --retries=3. There can be only one HEALTHCHECK; the last one wins. HEALTHCHECK NONE disables an inherited check.

The probe hits Day 19’s /health on loopback, not /metrics and not localhost as a hostname you have not proven. Alpine’s BusyBox wget is already in eclipse-temurin:21-jre-alpine-3.24 — do not apk add curl for this unit. Exec form matches Day 25: a JSON array, so the probe is not a shell wrapper. Kubernetes httpGet probes run from the kubelet, not from a binary in the image; they wait.
