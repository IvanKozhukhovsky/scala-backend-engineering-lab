H2 versus Postgres

Days 22–23 already tested the persistence program: bind parameters, one transact, Flyway files on classpath:db/migration. That is still the fast suite. It never started PostgreSQL. H2 accepted the same CREATE TABLE. It is not the engine you will run in production.1

Docker’s replace-H2 guide is blunt: in-memory H2 “doesn’t behave exactly like the real database.” Features such as ON CONFLICT are a Postgres dialect. Keep H2 for ConnectionIO and Flyway mechanics. This unit’s skill is a live catalog.

A local install on port 5432 has the same smell as the Redis example in the Testcontainers quickstart: it works only if every laptop and CI image already has that server, and parallel tests share one catalog. The module starts a container instead, maps a random host port, and waits until Postgres has logged that it is ready — twice, with a 60s timeout, already configured on PostgreSQLContainer.2

Postgres module, Testcontainers 2.0.5: artifact org.testcontainers:testcontainers-postgresql. Package is org.testcontainers.postgresql — not org.testcontainers.containers (that was 1.x). You need a Docker-API runtime. JUnit @Container waits; this repo is MUnit, so we wrap start / stop ourselves.

PostgreSQLContainer is a Resource

Constructing the object does not pull an image and does not listen. start() is the session: discover Docker, pull if needed, run, wait. stop() deletes the container. That is the same split as Flyway load versus migrate, and as Ember .build versus Resource.use. 

import org.testcontainers.postgresql.PostgreSQLContainer

val quotesImage = "postgres:16-alpine"

def quotesContainer: PostgreSQLContainer =
  new PostgreSQLContainer(quotesImage)

def quotesPg: Resource[IO, PostgreSQLContainer] =
  Resource.make(IO {
    val pg = quotesContainer
    pg.start()
    pg
  })(pg => IO { pg.stop() })

def withQuotesPg[A](run: (String, String, String) => IO[A]): IO[A] =
  quotesPg.use { pg =>
    run(pg.getJdbcUrl, pg.getUsername, pg.getPassword)
  }

After start, pass those three strings into Day 23’s Flyway and Day 22’s Transactor.fromDriverManager with org.postgresql.Driver. Default database, user, and password are test — not H2’s sa. getJdbcUrl is jdbc:postgresql:// plus getHost() plus the mapped 5432. That is the real driver. Keep rateOf as Map.get. 

def postgresXa(url: String, user: String, password: String) =
  Transactor.fromDriverManager[IO](
    driver = "org.postgresql.Driver",
    url = url,
    user = user,
    password = password,
    logHandler = None
  )

def migrateQuotesPg(url: String, user: String, password: String): IO[Int] =
  IO {
    Flyway.configure()
      .dataSource(url, user, password)
      .locations("classpath:db/migration")
      .load()
      .migrate()
      .migrationsExecuted
  }

withQuotesPg { (url, user, password) =>
  val xa = postgresXa(url, user, password)
  migrateQuotesPg(url, user, password) *>
    seedRates.transact(xa) *>
    RateRepository(xa).find("EUR")
}

select version() on this catalog contains PostgreSQL. H2’s version() does not. Same V1__ / V2__ files. Same transact rule: two sessions are two commits.

Read the URL; do not hide start

JDBC support also offers jdbc:tc:postgresql:…:///databasename. The page says Testcontainers will start a container “automagically,” and that host, port, and database name in that URL are ignored. By default that container stops as soon as the last connection closes.3

transact always closes the connection. That is the same class of bug as H2 mem without DB_CLOSE_DELAY=-1, except now the whole Postgres disappears. TC_DAEMON=true papers over it. We do not use the jdbc:tc: driver as the skill.

Hikari postgresPool.use is now a legal inner Resource — you finally have a live URL. Tests may still use DriverManager. Do not delete the H2 suites; they stay the fast check. Packaging the app image is the next unit — a different image from postgres:16-alpine.

Primary source Read the Testcontainers Postgres module through container creation and the Maven/Gradle pin (testcontainers-postgresql 2.0.5; you still need the Postgres JDBC driver — this repo already has doobie-postgres). Read PostgreSQL module examples for new PostgreSQLContainer(DockerImageName.parse("postgres:16-alpine")); postgres.start(). Read JDBC support through Database container objects (getJdbcUrl / getUsername / getPassword). Treat the jdbc:tc: URL scheme as something to recognise, not as the API you write (stop before init scripts, TC_DAEMON, and TC_TMPFS as skills). Skim the JUnit 4 Quickstart through “make sure our code can talk to the container” (getHost, mapped port — do not hard-code localhost:6379). Skip @Rule as a skill; this repo wraps start / stop in Resource.make. Skim container runtime requirements (Docker Desktop / Docker Engine).
