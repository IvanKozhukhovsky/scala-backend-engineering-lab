A row is not a Map

The in-memory catalog is a Map[String, Int]: the key is the currency code, the value is cents. A relational table stores the same facts as rows. The key becomes a primary key. Each field becomes a column with a SQL type. Nullability is explicit: NOT NULL maps to Int; a nullable column maps to Option[Int].1

doobie’s homepage: it is not an ORM and not a relational algebra. You write SQL. It maps rows to Scala types. This repo pins doobie-core 1.0.0-RC13 (org.typelevel, package org.typelevel.doobie). Postgres, Hikari, and H2 wait.
Scala SQL
RateRow.code rate.code VARCHAR PRIMARY KEY
RateRow.cents rate.cents INTEGER NOT NULL
rateOf("EUR") one row whose code is EUR, or none 
CREATE TABLE rate (
  code  VARCHAR NOT NULL PRIMARY KEY,
  cents INTEGER NOT NULL
)

final case class RateRow(code: String, cents: Int)

query[RateRow] maps columns by position, in SELECT-list order, to case-class fields in declaration order. select cents, code still compiles and silently swaps the fields at runtime. Name the columns in field order.2

Selecting Data: a case class is a supported row type. Shapeless records, nested products, and Stream are later. This unit reads Query0.sql — Diagnostics on the query value.

sql interpolator is a PreparedStatement

$code inside sql"…" looks like string interpolation. It is not. doobie builds a PreparedStatement and sets the value with setString / setInt. In the SQL text the parameter is ?. The hostile string never becomes syntax. s"…$code" is concatenation: it is how SQL injection is written.3

Parameterized Queries: interpolated values need a Put instance (JDBC types, including String and Int). Do not quote $code — where code = '$code' becomes the literal '?', which is not a bind parameter. 
import org.typelevel.doobie.*
import org.typelevel.doobie.implicits.*

def findRate(code: String): Query0[RateRow] =
  sql"select code, cents from rate where code = $code".query[RateRow]

def insertRate(row: RateRow): Update0 =
  sql"insert into rate (code, cents) values (${row.code}, ${row.cents})".update

.query[A] reads rows. .update modifies them (INSERT / UPDATE / DDL). Both values expose .sql so a test can assert on the statement without a database. rateOf stays the pure Map — SQL is a new description of the same lookup, not a replacement yet.

ConnectionIO is a description

findRate(code).option has type ConnectionIO[Option[RateRow]]: zero or one row, like Map.get. .unique demands exactly one row. insertRate(row).run is ConnectionIO[Int] — rows affected. Constructing any of these does not connect. A Transactor turns ConnectionIO into IO the way unsafeRunSync runs IO. That edge is the next unit.4

Connecting: ConnectionIO[A] needs a java.sql.Connection later. transact also starts a transaction. Do not add Transactor.fromDriverManager, a JDBC URL, or H2 here. Print findRate("EUR").sql if you want to see the ? — Day 21’s @main does that.
