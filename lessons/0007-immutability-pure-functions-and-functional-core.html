Change by copying

Day 04 already did this: alice.copy(age = 24) produced a second User while alice stayed 23. That is the Scala 3 Book’s rule for functional code: val, immutable collections, case classes with copy. You do not mutate the value in place.1

Scala 3 Book, Immutable Values: create vals; use List / Vector / immutable Map; update a case class with copy.

filter and map on a List are the same idea: they return another list. The input list is still there. You already wrote that pipeline in Days 02–03.

Same inputs, same output

A function is pure when the result depends only on the arguments and the implementation, and the function does not change the world around it. Call it with 2 forever: you keep getting 4.2

Scala 3 Book, Pure Functions: no mutated parameters, no hidden state, no “back doors” to console, files, databases, or the network.

clamp, pageOffset, and parseLimit were already pure — that is why MUnit and ScalaCheck could treat them as a spec. The Book’s impure list is the opposite of that: println, System.currentTimeMillis, throwing sys.error. A return type of Unit is a warning: you probably called it only for a side effect. 

case class Wallet(balanceCents: Int)

def debit(wallet: Wallet, amountCents: Int): Option[Wallet] =
  if amountCents <= 0 || amountCents > wallet.balanceCents then None
  else Some(wallet.copy(balanceCents = wallet.balanceCents - amountCents))

debit(Wallet(1000), 400) is always Some(Wallet(600)). The input wallet is unchanged. There is nothing to mock.

Pure cake, impure icing

A service that never talks to the world is useless. The Book’s recommendation is the whole skill for this unit: write a core of pure functions, then wrap it with an impure layer that reads and writes.3 Gary Bernhardt named that split functional core, imperative shell.4

Scala 3 Book, Pure Functions, “But impure functions are needed…”: “a core of pure functions that are wrapped with other functions to interact with the outside world” — “impure icing on top of a pure cake.”
Gary Bernhardt, Boundaries (2012). The core talks in values; the shell talks to stdin, stdout, disk, and the network. Tests of the core need no doubles. Stop before an IO type — the Book flags that as later, and this curriculum does too (scala-014). 
def printDebit(wallet: Wallet, amountCents: Int): Unit =
  debit(wallet, amountCents) match
    case Some(next) => println(s"balance ${next.balanceCents}")
    case None       => println("refused")

printDebit is allowed to be boring: one call, one match, I/O. The rule “is 400 allowed?” lives in debit. Tests call debit. If a later handler needs the time, the shell reads the clock and passes now in — the core still does not reach outside.
