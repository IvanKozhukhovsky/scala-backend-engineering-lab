The spec is the expected value

Day 9 already wanted a literal from a spec, not from the function under test. Kent Beck’s Canon TDD names the same failure mode: copying the value the code just computed into the expected side “defeats double checking.”1 This unit’s independent source is docs/capstone/quotes.openapi.yaml for documented operations, plus RFC 9110 for a method the document simply does not list.

Kent Beck, Canon TDD (2023). Fowler’s TDD bliki is the short three-step companion: write a test, make it pass, then optionally refactor.

OpenAPI still does not list POST on /health. That absence is not a 404 in the spec. RFC 9110: the server MUST send 405 and an Allow header naming the methods that resource currently supports.2 ADR 1 already recorded that consequence. Tests for omitted methods assert 405 + Allow; they do not hunt for a 405 response object in the YAML.

RFC 9110 §15.5.6 and §10.2.1 Allow. 405 means the method is known but not supported by this target resource.

One failing test, then green

Canon TDD: write a test list (here, the OpenAPI operations plus 405 cases), turn exactly one item into a runnable test, change the system until that test passes, then take the next item. The common screw-up is converting the whole list into concrete tests and only then writing code — Beck calls that rework waiting to happen; this lab’s TDD notes call it horizontal slicing.3

In this repository the suite is verifier-owned, so Day30Suite already exists. Your loop is still one red test at a time: run it, implement that path, then the next. Do not paste Day 20’s routes and rename strings.

http4s still does not need a port for that loop. HttpRoutes is Request => F[Response]. Construct a Request, app.run, read status and JSON. Ember waits until the contract is green; one live GET /health then proves the same HttpApp is serveable.4 MUnit: a test body with no assertion still passes — that is not red.

http4s Service and DSL: you do not need a server to test a route. This repo pins http4s-dsl / Ember 0.23.36. MUnit tests: an empty body does not crash, so it counts as success. 
test("GET /health returns the injected name"):
  val req = Request[IO](Method.GET, uri"/health")
  assertEquals(statusOf(req), Status.Ok)
  assertEquals(
    app.run(req).flatMap(_.as[HealthOut]).unsafeRunSync(),
    HealthOut("quotes")
  )

Green for that slice is one DSL case. rateOf stays Map.get. Persistence is named in the architecture note; it is not wired here — that is scala-031. 

case GET -> Root / "health" =>
  Ok(HealthOut(config.name))
case _ -> Root / "health" =>
  MethodNotAllowed(Allow(GET))

Review is a second hat

Beck: do not mix refactoring into making the test pass. Make it run, then make it right. Fowler’s third step is that optional tidy. This lab puts the second hat in /review-exercise: after green, check the seams the architecture named.

A green suite that maps POST /health to 404, or that looks up rates with sql"…".query.transact, has the wrong design even if some tests were deleted to stay green. Do not edit the tests to match a weaker contract. Production hardening, docs, and release wait for scala-032.

Primary source Read Kent Beck Canon TDD through step 3 (one test, make it pass; do not paste actuals into expected). Skim Fowler Test Driven Development for the red–green–refactor naming. Read RFC 9110 405 (MUST include Allow). Skim http4s Service — testing with a constructed Request, then Ember only when the contract is green. Stop before Tapir, codegen, Swagger UI, Flyway in routes, munit-cats-effect, and Router / <+>.
