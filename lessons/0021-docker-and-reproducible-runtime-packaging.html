Image, container, recipe

Docker’s own wording is the split. A container image is a standardized package: files, binaries, libraries, configuration. It is immutable. A container is an isolated process started from that package — portable because the process does not depend on what happens to be installed on the host.1

Day 24 already used this: Testcontainers pulled postgres:16-alpine (image) and start() ran a container. That image’s process is Postgres. This unit’s image’s process is ours.

A Dockerfile is the text recipe the builder reads: FROM the base image, WORKDIR, COPY files in, ENV for a running container, CMD for the default command. The recipe is not a running process. Building it produces an image. docker run is the session.

JRE plus JAR, not the laptop

This repository already pins JVM 21. The runtime image should too. Eclipse Temurin’s official image shows the shape: copy a JAR, then CMD ["java", "-jar", …]. We pin eclipse-temurin:21-jre-alpine-3.24 — Java 21, a JRE (the process is not going to compile), Alpine 3.24 rather than a floating latest.2

Docker Official Image eclipse-temurin. The Hub example uses FROM eclipse-temurin:25; this repo is JVM 21, so the 21 JRE Alpine tag. A JDK image would ship a compiler the runtime does not need. jlink custom runtimes wait.

CMD in exec form is a JSON array. It does not start a shell. java is PID 1. The ENV instruction persists into the running container; docker run --env overrides it. Ciris already reads process env at the rim — the Dockerfile does not call rateOf. 

FROM eclipse-temurin:21-jre-alpine-3.24
WORKDIR /app
COPY quotes.jar quotes.jar
ENV QUOTES_CODE=EUR
CMD ["java", "-jar", "quotes.jar"]

RuntimeImage in Day25.scala is that contract as data. dockerfileOf renders it. Building the case class does not talk to Docker — the same “description until the edge” split as IO and Flyway load.

scala-cli package, then docker run --env

Scala CLI’s package command is restricted: pass --power (or scala-cli config power true). An assembly is a fat JAR: your bytecode plus dependencies, nothing downloaded at first launch. Default assemblies add a bash preamble. --preamble=false leaves a JAR java -jar can run — the form Temurin’s CMD expects. 

scala-cli --power package . --assembly --preamble=false \
  -o packaging/quotes/quotes.jar --main-class day25.Day25
docker build -t quotes:0.1.0 packaging/quotes
docker run --rm --env QUOTES_CODE=GBP quotes:0.1.0

This lab has many IOApp objects — --main-class picks Day 25. *.jar is gitignored; the Dockerfile still COPYs the name you produce next to it. package --docker --docker-from eclipse-temurin:21-jre-alpine-3.24 --docker-image-repository quotes is the one-command path. The default tag is latest; pass --docker-image-tag if you use it. We keep a checked-in Dockerfile so the recipe is reviewable without invoking Docker in every test.

A whole-repo assembly still contains Day 24’s Testcontainers (it is a compile dependency, not test.dep). The image is reproducible; it is not yet slim. Splitting a service module waits for the capstone. Do not install Scala CLI inside the runtime to paper over that.

loadQuotesPackConfig is Ciris: env("QUOTES_CODE") with a default of EUR. centsFor takes a PackConfig. rateOf stays Map.get. A token does not belong in ENV — Day 19 already wrapped secrets; docker history would print a baked token. Compose, USER, health checks, and CI image builds wait.
