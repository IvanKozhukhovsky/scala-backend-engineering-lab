forAll is “for every generated value”

An example names one input and one expected value. A property names a rule that should hold for a whole class of inputs. ScalaCheck generates those inputs and checks the rule, by default 100 times.1

ScalaCheck, User Guide: you specify behaviour; “all test data are generated automatically.” forAll is the usual way to write a universally quantified property.

This workspace already uses MUnit 1.0.4. Property tests need the extra module munit-scalacheck 1.0.0 (there is no 1.0.4 of that artifact). Extend munit.ScalaCheckSuite and write property instead of only test.2

MUnit, ScalaCheck: property is almost test, but the body must be a ScalaCheck Prop. You can still call assertEquals inside forAll. 
import munit.ScalaCheckSuite
import org.scalacheck.Prop.forAll

def clamp(value: Int, lo: Int, hi: Int): Int =
  if value < lo then lo
  else if value > hi then hi
  else value

class Day10Suite extends ScalaCheckSuite:
  test("clamp 150 into 1 to 100 is 100"):
    assertEquals(clamp(150, 1, 100), 100)

  property("when lo <= hi, clamp stays in [lo, hi]"):
    forAll { (value: Int, lo: Int, hi: Int) =>
      (lo <= hi) ==> {
        val got = clamp(value, lo, hi)
        got >= lo && got <= hi
      }
    }

test still belongs here: it pins a known HTTP-style example (a query limit of 150 becomes 100). property is the rule a pagination or timeout clamp must obey for whatever integers ScalaCheck draws. Import propBoolean next to forAll so a Boolean on the left of ==> becomes a Prop.3

ScalaCheck, Conditional Properties: ==> keeps a case only when the premise holds. Import org.scalacheck.Prop.propBoolean.

A failure comes back small

The User Guide’s sqrt property is false for negatives. ScalaCheck first found a large Int, then minimised it to -1 before reporting.4 That is the point of a property failure: you get a small counterexample, not a stack of random noise.

ScalaCheck, User Guide quick example, and Test Case Minimisation. ARG_0 is the shrunk value; ARG_0_ORIGINAL is what failed first.

MUnit also prints a seed so you can replay a flaky draw. That knob lives on the ScalaCheck cheat sheet; you do not need it for the exercise.

Generate the interesting set

==> discards cases where the premise is false. If the premise almost never holds, ScalaCheck runs out of tries and reports that it gave up — not that the property passed.5

ScalaCheck, Conditional Properties: (n == 0) ==> … on a random Int is the textbook “Gave up after only 4 passed tests. 500 tests were discarded.” Prefer a tighter generator over turning the discard ratio up.

lo <= hi is true often enough, so implication is fine there. “The value is already inside [lo, hi]” is rare for three independent Ints. Generate that set instead: 

import org.scalacheck.Gen

property("a value already in [lo, hi] is unchanged"):
  forAll(Gen.choose(-1000, 1000), Gen.choose(0, 2000), Gen.choose(0, 2000)) {
    (lo, width, rawOffset) =>
      val hi = lo + width
      val value = lo + math.min(rawOffset, width)
      assertEquals(clamp(value, lo, hi), value)
  }

Gen.choose(a, b) draws inclusive bounds you name. Pass those generators to forAll when you do not want the default Arbitrary[Int] (the whole integer line).6

ScalaCheck, Universally quantified properties: val smallInteger = Gen.choose(0,100) then Prop.forAll(smallInteger) { n => … }. Do not write a custom Arbitrary in this unit.

Invariants, not the method body

Day 09’s tautology still applies. A property that pastes clamp’s if into the expected side cannot disagree with a bug: 

// independent — a person can check “in range” without reading clamp
got >= lo && got <= hi

// tautology — this is the implementation, twice
clamp(value, lo, hi) == (
  if value < lo then lo
  else if value > hi then hi
  else value
)
