A workflow is a recipe that fails closed

GitHub Actions is a CI platform: a workflow is a YAML file under .github/workflows. An event starts a run. A job is a list of steps on one runner. A step is either uses: (a reusable action) or run: (a script). The recipe is not a running job — the same split as a Dockerfile versus docker run.1

on names events. A bare pull_request: still needs the colon. push.branches keeps this workflow off feature branches you have not opened as a PR.

scripts/verify.py already runs three commands: progress.py check, scala-cli fmt --check ., scala-cli test .. The workflow’s run: steps are those commands on a GitHub-hosted VM. A non-zero exit fails the step. continue-on-error: true would let the job pass anyway — that is not a gate.

The permissions key limits GITHUB_TOKEN. This job only checks out and runs commands, so contents: read. write-all is the opposite of minimum access. Action SHA pinning and non-root Docker USER wait for the security unit.

QualityPipeline in Day26.scala is that contract as data. workflowOf renders it. Building the case class does not talk to GitHub.

Pin the runner, the action, the CLI

GitHub’s runner docs: the -latest label is the latest stable image GitHub provides, and they move it. Today ubuntu-latest and ubuntu-24.04 are the same Ubuntu 24.04 image. The pin is the versioned label, for the same reason Day 25 did not tag the quotes image latest.2

GitHub-hosted runners and the runner-images README: specify an OS version to avoid an unplanned migration. You still cannot pin a particular weekly image rebuild.

The scala-cli-setup action can take scala-cli-version: "latest". This lab pins v1.16.0 on the action and "1.16.0" on the CLI it installs. Tests compare .github/workflows/ci.yml to workflowOf(quotesPipeline) exactly.

Dependabot sees YAML; Scala CLI does not

Dependabot version updates read .github/dependabot.yml: version: 2, then one updates entry per ecosystem. github-actions with directory: / watches .github/workflows. docker with directory: /packaging/quotes watches that Dockerfile’s FROM. Each entry needs schedule.interval — this lab uses weekly. Dependabot opens a PR; CI is what tells you whether the bump is safe.3

The ecosystem list includes sbt. This repository is Scala CLI. A package-ecosystem: sbt entry would look for build.sbt, which we do not have.

Scala library pins live in project.scala. Scala CLI’s using directives distinguish using dep (compile classpath, packaged into an assembly) from using test.dep (test sources only). MUnit is test.dep. Testcontainers is still using dep in this lab because Day 24’s @main starts a container — moving it would break that main, not “fix hygiene.” Dependabot cannot see those lines. A Scala CLI “outdated” hint is not a CI failure; bump a pin only with a docs rationale, the way project.scala already comments. 

version: 2
updates:
  - package-ecosystem: github-actions
    directory: /
    schedule:
      interval: weekly
  - package-ecosystem: docker
    directory: /packaging/quotes
    schedule:
      interval: weekly

Independent practice

Tests inspect the recipe. They do not start a GitHub run. Run the worked example:
