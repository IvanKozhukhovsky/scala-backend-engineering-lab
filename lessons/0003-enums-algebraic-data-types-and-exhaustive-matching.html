Retrieve first You wrote validPort as Either[String, Int], with messages such as Left("Port is not in distance 1 <= port <= 65535"). Before reading on: if a later function must treat “not an integer” differently from “out of range”, what can the type Either[String, Int] not do for you?

Named values

The Scala 3 Book starts from a type that is exactly a set of names. That is an enum.1

Scala 3 Book, Algebraic Data Types, section Enumerations. The same idea in domain language: “if you want to model data with different alternatives, use the enum construct” — FP Modeling. 
enum Role:
  case Admin, Member, Guest

Cases are members of the companion object, so you write Role.Admin (or import Role.* and then Admin).2 A string "admin" can be misspelled; Role.Admn does not compile.

Scala 3 Reference: Enumerations — this defines a sealed class Role with three values on Role’s companion. 
def describeRole(role: Role): String =
  role match
    case Role.Admin  => "full access"
    case Role.Member => "limited access"
    case Role.Guest  => "read only"

You already matched on Some / None and Success / Failure. This is the same shape: one case per inhabitant.

Cases that hold data

Some alternatives are just names. Some carry a payload. The Book reconstructs Option as an enum: Some holds a value, None does not.3 A parameterized case is shorthand for a tiny case class that extends the enum.

Same Book chapter, section Algebraic Datatypes (ADTs): enum Option[+T]: case Some(x: T); case None. You will keep using the library Option; this is the shape, not a replacement. 
enum PortError:
  case NotAnInteger(raw: String)
  case OutOfRange(port: Int)

Named values and payloads are two ends of one construct, not two languages. The Book’s hybrid Color mixes both: Red / Green / Blue plus Mix(mix: Int).4 You do not need GADTs for this unit — stop before that section of the chapter.

Same Book chapter, the Color example that adds case Mix(mix: Int). Recursion (enum Nat, enum List) is also there; leave it for later.

The compiler names the miss

Because an enum is sealed, a match is checked for missing cases. Drop Role.Guest and Scala 3 emits E029: “match may not be exhaustive” — and it names Guest.5

E029: Pattern Match Exhaustivity. The Tour of Scala section Sealed types is the same rule on sealed trait: ignore the warning, hit the missing case at runtime, and you get a MatchError.

Day 04 used case _ on Int because Int is not a closed set. E029 lists case _ as one way to silence the warning. On a domain enum that is the wrong instinct: a new error case should fail the build, not disappear into “other”.

Either of an error enum

Either[String, Int] can hold any sentence. The caller cannot ask the type “was this a parse failure or a range failure?” — only read the text and hope. Put the enum on the left: 

def validPort(port: Int): Either[PortError, Int] =
  if port >= 1 && port <= 65535 then Right(port)
  else Left(PortError.OutOfRange(port))

def readPort(raw: String): Either[PortError, Int] =
  Try(raw.trim.toInt) match
    case Failure(_) => Left(PortError.NotAnInteger(raw.trim))
    case Success(n) => validPort(n)

Consume the error with the same exhaustive match you used on Role. The payload comes out in the pattern, the way Success(n) unwraps the integer: 

def describePortError(error: PortError): String =
  error match
    case PortError.NotAnInteger(raw) => s"not an integer: $raw"
    case PortError.OutOfRange(port)  => s"out of range: $port"
Primary source Read Scala 3 Book — Algebraic Data Types through the hybrid Color example. Skip Generalized Algebraic Datatypes. Then skim E029 so you recognise the warning when you omit a case. Keep the enums / ADT cheat sheet open while you code.
